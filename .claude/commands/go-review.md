# Goコードレビュー

**go-reviewer** エージェントを呼び出して包括的なGo固有のコードレビューを実施する。

## 実行内容

1. **Go変更の特定**: `git diff` で変更された `.go` ファイルを検出
2. **静的解析の実行**: `make lint` (gofmt + golangci-lint)
3. **セキュリティスキャン**: `make gosec-scan`
4. **アーキテクチャ検証**: `make arch-check` (Feature間依存チェック)
5. **並行処理レビュー**: ゴルーチン安全性、チャネル使用、Mutexパターン
6. **イディオマティックGoチェック**: Go規約とベストプラクティスの準拠確認
7. **日本語ルール確認**: コメント・ログ・エラーメッセージの日本語化確認
8. **レポート生成**: 重要度別に問題を分類

## 使用タイミング

- Goコードの作成・修正後
- Goの変更をコミットする前
- Goコードを含むPRのレビュー時
- 新しいFeatureパッケージの実装後

## レビューカテゴリ

### CRITICAL(修正必須)
- SQL/コマンドインジェクションの脆弱性
- 同期なしのレースコンディション
- ゴルーチンリーク
- ハードコードされた認証情報
- `#nosec` の使用
- Feature間の直接import
- エラーの `_` 無視(クリティカルパス)

### HIGH(修正推奨)
- コンテキストなしのエラー返却
- panicの代わりにエラー返却すべき箇所
- Contextの非伝播
- testify/suite パターンの違反
- 日本語コメント・ログの不足

### MEDIUM(検討)
- 非イディオマティックなコードパターン
- スライスの事前割り当て不足
- 全角括弧の使用

## 実行される自動チェック

```bash
# フォーマット + 静的解析
make lint

# セキュリティスキャン
make gosec-scan

# Feature間依存チェック
make arch-check

# レースディテクション
go build -race ./...
```

## 承認基準

| ステータス | 条件 |
|----------|------|
| 承認 | CRITICALまたはHIGHの問題なし |
| 警告 | MEDIUMの問題のみ(注意してマージ可能) |
| ブロック | CRITICALまたはHIGHの問題あり |

## 他のコマンドとの連携

- `/go-test` を先に実行してテストをパスさせる
- `/go-build` でビルドエラーが発生した場合に使用
- `/go-review` をコミット前に実行
